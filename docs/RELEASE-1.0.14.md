# Gramix 1.0.14 / Android 39

## Состав

- Офлайн-черновик ручного ввода: название и ингредиенты сохраняются на устройстве отдельно для каждого Firebase UID. Очистка — только после подтверждённой сервером записи блюда и только если черновик с тех пор не изменился. Ошибки хранилища показываются явно. Фото и результаты распознавания не являются офлайн-очередью.
- Обратная связь в профиле: 5–2000 символов, до 5 сообщений за скользящие 24 часа. Worker определяет пользователя по токену, а не по полям формы. D1 outbox повторяет доставку в личный бот ошибок; группа регистраций не используется. Хранение сообщений — 14 дней, максимум 12 попыток доставки.
- Web: внутренние переходы используют replace, а не push. Внешняя история браузера не блокируется. Manifest задаёт standalone, scope / и стабильный start_url /. Обычная вкладка сохраняет адресную строку; старый ярлык может потребовать повторного добавления на главный экран.
- Офлайн-оболочка web кэширует только собственные статические ресурсы. API, Firebase, токены и документы пользователя не входят в Cache Storage. Обновление service worker не принудительное: открытая форма не перезагружается. Для первого офлайн-запуска необходимо хотя бы раз открыть эту версию с интернетом.
- Android: шаги читаются после добровольного подключения на главной; обновляются при открытии/возврате, видимости главной и раз в минуту, пока она открыта. Без разрешений дневник работает.
- Пушей, расписаний питания, избранного, повторения блюд и отмены удаления в этом обновлении нет.

## Шаги и норма

Основной источник — агрегат StepsRecord.COUNT_TOTAL из Health Connect за локальные сутки. Не фильтруем по пакету источника: это сохраняет дедупликацию и совместимость с изменением Android SPN в июне 2026.

Резерв — TYPE_STEP_COUNTER. Храним отдельные контрольные точки по аккаунту: локальный день, timezone, boot count, последнее показание, сумму известных сегментов. При сбросе датчика/перезагрузке не добавляем неизвестный промежуток. При смене дня или timezone начинаем сегмент заново. Не суммируем Health Connect и датчик.

Датчик слушается только во время работы приложения; нет foreground service, постоянного уведомления и обещания полного фонового подсчёта. Данные до первого показания/между неизвестными границами суток восстановить нельзя. UI помечает резервный итог как неполный.

Шаги не отправляются на сервер или в Telegram. Локальные контрольные точки исключены из Android backup/device transfer. Отключение удаляет контрольные точки текущего аккаунта, но системное разрешение пользователь отзывает в Health Connect/Android.

### Формула оценки v1

PDF задаёт activeKcal = steps × kcalPerStep, но не фиксирует числовой коэффициент. В реализации:

- примерная длина шага = рост в сантиметрах × 0.414;
- kcalPerStep = 0.5 × вес в кг × длина шага в км;
- activeKcal = steps × kcalPerStep;
- alreadyIncluded = 3000 × kcalPerStep + BMR × (activityCoefficient − 1.2);
- extra = max(0, round(activeKcal − alreadyIncluded));
- todayGoal = сохранённая базовая норма + extra.

3000 шагов — консервативное продуктовое допущение для обычного движения, а не медицинский порог. Дополнительная активность сверх sedentary вычитается, поскольку уже включена в существующую норму. Поэтому на умеренном/высоком уровне активности прибавка часто будет 0 — это предотвращает двойное начисление.

Коррекция работает только для стандартного взрослого профиля с проверенными диапазонами и нормой, совпадающей с существующей формулой приложения. Несовершеннолетним, неполным профилям и вручную изменённым целям норма автоматически не повышается. Это приблизительная оценка ровной ходьбы, не измерение обмена веществ и не медицинская рекомендация. Темп, уклон, заболевания и индивидуальная длина шага не измеряются.

Результат вычисляется заново из сегодняшнего итога: повторный запуск не начисляет те же калории повторно. Базовая норма в базе не перезаписывается. Web и историческая статистика продолжают использовать базовую норму; Android-прибавка локальна для текущего дня.

## Android-совместимость

Health Connect 1.1.0 — стабильная Jetpack-версия. Вызовы доступны только на API 28+ и при наличии провайдера. Android 24–27 сохраняют резервный датчик; minSdk не повышен. Для этого документирован overrideLibrary с runtime-ограничением, java.time поддержан desugaring. Перед публикацией в Google Play потребуется декларация чтения шагов в Health apps/Health Connect.

## Проверки и источники

- JS unit: расчёт, повторные показания, неправильные значения, смена дня, защищённые цели, все 8 языков.
- Android unit: сброс счётчика, смена дня/timezone, повторное показание.
- Browser reliability: сохранение вкладок, история replace, перезагрузка черновика, аккаунтная изоляция, повреждённый черновик, форма обратной связи.
- Production-shell test: warm + cold offline launch из реального service worker без серверных данных, отсутствие API в кэше. В тестовом build подставляется отдельная тестовая identity, production-конфиг не изменяется.
- Worker: авторизация, неприсваиваемый пользователем ID, лимиты и idempotency, доставка только в личный канал.
- Реальная точность шагов требует проверки ходьбой на физическом телефоне; эмулятор не заменяет этот тест.

Официальная документация: [Android steps](https://developer.android.com/health-and-fitness/health-connect/features/steps), [Health Connect setup](https://developer.android.com/health-and-fitness/health-connect/get-started), [Jetpack releases](https://developer.android.com/jetpack/androidx/releases/health-connect).

Основание для приближённой стоимости ровной ходьбы: [исследование уравнения ACSM](https://pmc.ncbi.nlm.nih.gov/articles/PMC3656435/). Коэффициент длины шага и вычет бытовой активности являются явными продуктовыми допущениями, а не точным медицинским персональным расчётом.

Отдельно замечено: npm audit сообщает 18 уязвимостей зависимостей, включая 3 critical. Массовое обновление зависимостей не включено в этот функциональный релиз; требуется отдельный разбор применимости и обновление с регрессией.
